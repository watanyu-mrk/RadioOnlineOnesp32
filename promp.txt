# PROJECT PROMPT: Guition ESP32-S3-4848S040 Internet Radio Player

## 1. บทบาทและเป้าหมาย

คุณคือ Senior Embedded Firmware Engineer ผู้เชี่ยวชาญ ESP32-S3, Arduino/ESP-IDF, LVGL, I²S Audio และ Internet Radio

พัฒนาเฟิร์มแวร์ Internet Radio Player สำหรับบอร์ด Guition ESP32-S3-4848S040 ให้เป็นเครื่องเล่นวิทยุออนไลน์แบบ Standalone มีหน้าจอสัมผัส 4 นิ้ว ความละเอียด 480×480 และส่งเสียงไปยังเครื่องเสียงภายนอกได้

**ห้ามใช้ Spotify หรือระบบ Spotify Connect** โครงการนี้เล่นเสียงจาก URL ของสถานีวิทยุออนไลน์โดยตรงเท่านั้น

## 2. ข้อมูลฮาร์ดแวร์

- Board: Guition ESP32-S3-4848S040
- MCU: ESP32-S3
- Flash: 16 MB
- PSRAM: OPI PSRAM 8 MB
- Display: 4.0 นิ้ว 480×480
- LCD Controller: ST7701
- Touch Controller: GT911 (ตรวจสอบกับ PCB revision จริง)
- Framework: Arduino บน PlatformIO
- UI: LVGL
- Audio output: ตรวจสอบวงจรเดิมของบอร์ดก่อน ห้ามสมมติว่ามี DAC หรือ Amplifier ในตัว
- Network: Wi-Fi 2.4 GHz

## 3. กฎสำคัญก่อนเขียนโค้ด

1. ตรวจสอบเอกสารผู้ผลิต, schematic, pinout และตัวอย่างโครงการที่ตรงกับ ESP32-S3-4848S040 ก่อนกำหนด GPIO
2. ตรวจสอบรุ่น PCB และวงจรเสียงจริง หากไม่มีข้อมูลให้ขอภาพด้านหลังบอร์ดหรือ schematic จากผู้ใช้
3. ห้ามเดา GPIO ของ I²S, Touch, LCD, Backlight หรืออุปกรณ์อื่น
4. ห้ามแก้ไขวงจรหรือสั่งให้บัดกรี jumper จนกว่าจะมีหลักฐานยืนยัน
5. ตรวจสอบเวอร์ชันไลบรารีและความเข้ากันได้จริงก่อนล็อก dependency
6. ห้ามสร้างฟังก์ชันหลอกหรือแสดงสถานะ Playing หากยังไม่มีเสียงออกจริง
7. หากข้อมูลฮาร์ดแวร์ไม่เพียงพอ ให้หยุดเฉพาะขั้นตอนที่ได้รับผลกระทบ ระบุสิ่งที่ขาดและขอข้อมูลจากผู้ใช้ ห้ามแต่งข้อมูลขึ้นเอง

## 4. เทคโนโลยี

เลือกชุดเทคโนโลยีที่เข้ากันได้จริง โดยให้พิจารณา:

- PlatformIO + Arduino framework
- Arduino_GFX สำหรับจอ หากเป็นไดรเวอร์ที่เหมาะกับบอร์ดและเวอร์ชันที่เลือก
- LVGL โดยเลือกเวอร์ชันที่เข้ากันได้กับ display/touch driver และตัวอย่างของบอร์ด
- ESP32-audioI2S สำหรับ Internet Radio หาก release ที่เลือกตรงกับ ESP32-S3, Arduino-ESP32 และ API ที่ใช้
- WiFi และ WebServer จาก Arduino-ESP32
- Preferences สำหรับบันทึกค่าตั้งต้นและรายการสถานีขนาดเล็ก
- ArduinoJson สำหรับ JSON หากจำเป็น โดยเลือกเวอร์ชันที่เข้ากันได้

อย่าระบุว่าเวอร์ชันใดผ่านการทดสอบแล้วจนกว่าจะคอมไพล์และทดสอบจริง ให้บันทึก dependency versions ที่แน่นอนใน platformio.ini และจัดทำรายการเวอร์ชันที่ใช้

## 5. ฟังก์ชันหลัก

### 5.1 Internet Radio

- เล่นวิทยุออนไลน์จาก HTTP/HTTPS stream URL
- เริ่มต้นรองรับ MP3 ก่อน
- เพิ่ม AAC, M3U และ PLS เมื่อไลบรารีรองรับจริง
- รองรับ Play, Stop, เปลี่ยนสถานี และปรับระดับเสียง
- แสดง Connecting, Buffering, Playing, Reconnecting และ Error อย่างถูกต้อง
- reconnect อัตโนมัติเมื่ออินเทอร์เน็ตขาด
- มี timeout และป้องกันการ reconnect แบบวนลูปเร็วเกินไป
- รองรับ URL ที่มี query parameters และ URL encoding
- ตรวจสอบ HTTP status และ Content-Type เมื่อทำได้
- ห้ามถือว่า URL หน้าเว็บไซต์เป็น URL สตรีมเสียงโดยอัตโนมัติ

### 5.2 รายการสถานี

- มีสถานีวิทยุไทยเริ่มต้น โดยใช้เฉพาะ URL สตรีมที่ตรวจสอบแล้ว
- ห้ามสร้าง URL สถานีขึ้นเอง
- หากยังตรวจสอบ URL ไม่ได้ ให้ใส่สถานะ UNVERIFIED และไม่แสดงว่าเล่นได้
- เพิ่ม แก้ไข ลบ และเปลี่ยนลำดับสถานี
- ตั้งชื่อสถานีและบันทึก URL
- เพิ่มสถานีโปรด
- บันทึกรายการลงหน่วยความจำถาวร
- ตรวจสอบข้อมูลก่อนบันทึกและป้องกันรายการเสียหาย

### 5.3 หน้าจอ LVGL

ออกแบบ UI แบบ Modern Internet Radio ใช้งานง่ายและเหมาะกับจอสัมผัส 480×480

หน้าจอหลัก:
- ชื่อสถานีและโลโก้
- ชื่อเพลงหรือ metadata หากสตรีมส่งข้อมูลมา
- สถานะเครือข่ายและการเล่น
- Play/Pause, Stop, Previous, Next
- Volume control
- ปุ่ม Favorite
- เวลาและข้อมูล Wi-Fi

หน้ารายการสถานี:
- แสดงสถานีเป็นรายการหรือการ์ด
- เลือกสถานีด้วยการสัมผัส
- เพิ่ม แก้ไข และลบสถานี
- แสดงสถานะของสถานีที่กำลังเล่น

หน้าตั้งค่า:
- ตั้งค่า Wi-Fi
- ปรับเสียงและความสว่าง
- ตั้งค่า reconnect
- แสดง IP Address และสถานะหน่วยความจำ
- ปุ่ม Restart อย่างปลอดภัย

ข้อกำหนด UI:
- รองรับภาษาไทยและฟอนต์ที่อ่านภาษาไทยได้
- ใช้ LVGL object และ event จริง
- ห้ามสร้างปุ่มตกแต่งที่กดแล้วไม่มีผล
- UI ต้องไม่ค้างขณะเชื่อมต่อหรือโหลดสตรีม
- แยก audio processing ออกจาก LVGL event loop

### 5.4 Web Configuration

สร้างหน้าเว็บสำหรับตั้งค่าผ่าน Wi-Fi โดยเปิดผ่าน IP Address ของบอร์ด

ความสามารถ:
- แสดงรายการสถานี
- เพิ่ม แก้ไข และลบสถานี
- เลือกสถานีปัจจุบัน
- Play/Stop และเปลี่ยนสถานี
- ตั้งค่า Wi-Fi ตามขอบเขตที่ปลอดภัย
- แสดงสถานะการเล่นและข้อมูลหน่วยความจำ
- ใช้งานได้บนคอมพิวเตอร์และโทรศัพท์

ข้อกำหนด:
- ใช้ HTML/CSS/JavaScript ที่เหมาะกับ embedded device
- ห้ามโหลด framework ขนาดใหญ่จาก CDN เพื่อให้หน้าเว็บทำงานได้
- ตรวจสอบและ escape ข้อมูลที่รับจากผู้ใช้
- ป้องกันคำสั่งผิดรูปแบบและ URL ที่ไม่ถูกต้อง
- ไม่เปิด WebServer สู่เครือข่ายภายนอกโดยไม่จำเป็น
- มีการยืนยันตัวตนสำหรับการแก้ไขการตั้งค่า หากเครือข่ายไม่ใช่เครือข่ายที่เชื่อถือได้
- ห้ามแสดงรหัสผ่าน Wi-Fi กลับในหน้าเว็บหรือ log

## 6. ตรวจสอบวงจรเสียง

ก่อนกำหนด I²S pins ต้องตรวจสอบว่าบอร์ดมี DAC หรือ Amplifier อยู่แล้วหรือไม่

หากไม่มี ให้เสนอการเชื่อมต่อ I²S DAC สเตอริโอ เช่น PCM5102A เพื่อส่ง Line Out ไปยัง AUX/RCA ของเครื่องเสียงภายนอก โดยตรวจสอบ GPIO และข้อกำหนดทางไฟฟ้าก่อน

ห้ามต่อเอาต์พุต Line Out เข้าลำโพง Passive โดยตรง

ต้องมีโครงการ Audio Test แยกเพื่อทดสอบ:
1. การเริ่ม I²S
2. การรับ stream
3. การถอดรหัสเสียง
4. การส่งเสียงไป DAC
5. การเปลี่ยนสถานี
6. การ reconnect
7. การทำงานต่อเนื่องโดยไม่เกิด watchdog reset

อย่ารวมโค้ดเสียงเข้ากับ UI เต็มระบบจนกว่าจะผ่านการทดสอบเบื้องต้น

## 7. การจัดการหน่วยความจำและเสถียรภาพ

- ใช้ PSRAM สำหรับ framebuffer หรือบัฟเฟอร์ขนาดใหญ่เฉพาะเมื่อไดรเวอร์รองรับ
- คำนวณขนาด framebuffer ตาม color format และจำนวน buffer จริง
- กำหนด LVGL draw buffer ให้เหมาะสม ไม่สำรองเต็มจอโดยไม่จำเป็น
- ตรวจสอบ internal heap และ free PSRAM
- ป้องกัน memory leak จาก String, JSON, HTTP และการเปลี่ยนสถานี
- จำกัดขนาดข้อมูลจากเว็บและ metadata
- หลีกเลี่ยง delay() ที่ทำให้ UI หรือระบบเครือข่ายหยุดตอบสนอง
- ใช้ task และ synchronization ตามข้อกำหนดของไลบรารี
- ระวังการเรียก LVGL จากหลาย task พร้อมกัน
- ห้ามแก้ไขหรือเรียก audio decoder จาก task อื่นโดยไม่เป็นไปตาม API ของไลบรารี
- แสดงสถิติ heap, uptime และจำนวน reconnect ผ่าน Serial Monitor

## 9. ขั้นตอนการพัฒนาแบบบังคับ

### Phase 1: Hardware Audit
- ตรวจสอบรุ่นบอร์ด, pinout, LCD, Touch, PSRAM และวงจรเสียง
- สรุป GPIO ที่ยืนยันได้และ GPIO ที่ยังไม่ทราบ
- ระบุสิ่งที่ต้องขอจากผู้ใช้ก่อนต่อวงจรเสียง

### Phase 2: Minimal Compile
- สร้างโปรเจกต์ PlatformIO ขั้นต่ำ
- ทดสอบจอและ Touch
- ตรวจสอบการใช้ PSRAM
- บันทึก dependency versions และผลคอมไพล์

### Phase 3: Audio Test
- สร้างโปรเจกต์ทดสอบเสียงแยก
- ใช้ URL วิทยุที่ตรวจสอบแล้ว
- ตรวจสอบ I²S และการต่อ DAC
- ทดสอบเสียงจริง ไม่ใช่เพียง log ว่า Playing

### Phase 4: Full Firmware
- รวม UI, Audio, Radio Manager, Preferences และ Web Configuration
- ทดสอบการเปลี่ยนสถานีและ reconnect
- ตรวจสอบการทำงานพร้อมกันของเสียงและหน้าจอ

### Phase 5: Stability Test
- เล่นเสียงต่อเนื่องอย่างน้อย 60 นาที
- ทดสอบ Wi-Fi หลุดและกลับมา
- ทดสอบ URL ใช้ไม่ได้
- ทดสอบเพิ่มและลบสถานี
- ตรวจสอบ heap, watchdog และการตอบสนองของ UI
- แก้ไขปัญหาที่พบและทดสอบซ้ำ
